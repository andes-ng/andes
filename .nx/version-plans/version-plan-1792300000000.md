Add AndesTree, a tree view with expand and collapse, single or multiple selection, cascading checkboxes, lazy loading, filtering with match highlighting, connector lines, drag-and-drop reordering with a keyboard alternative, virtual scrolling and the WAI-ARIA treeview keyboard model, plus pure helpers (`andesFlattenTree`, `andesConductCheck`, `andesMoveTreeNode`, `andesFilterTree`) for working with tree data. A check box pops, draws its tick and rings softly when a click changes it, with the checkbox's own motion. `andesTreeFromFlat` builds the nodes from flat data that names each item's parent (`id` / `pId`). A `switcherIcon` template replaces the expand arrow. The empty state draws a muted tray above its text. `disabledKeys` disables nodes on top of their own flag. Connector lines run unbroken from row to row, through the gap between rows: the open box's stem meets its children's elbows, a parent's tick ends on its 14px box and a leaf's tick reaches its label; `showLeafIcon` puts a file glyph or a template in each leaf's switcher instead. A draggable tree opens every row with a six-dot grip (`dragHandle` hides it), draws the drop line in the gap between rows at the level the node would land on (one level in, with a tinted target, for a drop inside), and reports `nodeDragStart`, `nodeDragEnter`, `nodeDragOver`, `nodeDragLeave`, `nodeDragEnd` and `nodeDrop`; the tree never changes `nodes` itself, the consumer applies a drop (for instance with `andesMoveTreeNode`), and the move is announced once `nodes` carry it. A multiple directory tree selects like a file browser (click, Ctrl / Cmd + click, Shift + click) and highlights a row as one full-width bar on hover. `autoExpandParent` opens the ancestors of the expanded keys, `getNodePath()` and `andesGetTreePath()` give the keys down to a node for a controlled scroll, and `classNames` / `styles` reach the tree's root, rows, icons and titles.
